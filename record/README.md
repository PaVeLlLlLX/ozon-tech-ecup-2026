# Контроль качества карточек товаров — Ozon E-CUP Students 2026

Решение задачи «Контроль качества»: по карточке товара (название, описание,
фотографии) определить, действительно ли товар относится к заявленной продавцом
категории. Оценка — среднее двоичных F1 по классу «не бан», посчитанных внутри
каждой из двух категорий.

## Устройство решения

Отправляемый вариант — `vlm_blend_rare2_a_t24`, он задан в `configs/submission.yaml`.

Основа — зрительно-языковая модель **Qwen3-VL-4B-Instruct**, дообученная методом LoRA
в две ступени. Модель получает карточку и фотографии товара и отвечает одним словом
«Да» или «Нет» на вопрос, относится ли товар к заявленной категории.

Ответ берётся из логитов первой позиции как

```
sigmoid( logsumexp(логиты «да») − logsumexp(логиты «нет») )
```

где в каждую сумму входит по пять написаний: «Да», « Да», «да», «Yes», « Yes» и
соответственно для «нет».

### Как складываются два источника

Оценка зрительной модели и вероятность линейной приводятся к **квантилям** относительно
распределений, снятых на отложенной выборке и сохранённых внутри весов связки. Вес
зрительной модели свой у каждой категории:

| категория | вес зрительной модели | порог |
|---|---|---|
| Легковоспламеняющиеся | 1.0 — линейная выключена | 0.9699 |
| БАД | 0.5 — поровну с линейной | 0.295 |

Вердикт — сравнение с порогом (`score >= порог`), а не отбор доли. Порог здесь
абсолютный: «оценка выше 96.99% отложенного распределения».

⚠ Порог и доля — разные правила, и подменять одно другим нельзя. Абсолютный порог
переносит на закрытые данные ту шкалу, на которой он подобран, и число названных
товаров получается таким, каким его дадут сами данные. Доля называет фиксированный
процент выборки. У этого варианта в весах связки поля `top_fraction` нет — значит
работает именно порог.

### Распознавание текста на фотографиях

Включено (`use_ocr: true`, два кадра на товар) и кормит **только линейную ветку**:
в `configs/vlm_sft.yaml` стоит `use_ocr: false`, поэтому в промпт зрительной модели
распознанный текст не попадает.

### ⚠ Настройки прогона берутся из `configs/vlm_sft.yaml`

`run.py` грузит именно его, а не `configs/vlm_sft_rented.yaml`, по которому шло обучение.
Числа там отличаются, и путать их нельзя:

| | обучение (`vlm_sft_rented.yaml`) | прогон (`vlm_sft.yaml`) |
|---|---|---|
| кадров на товар | 5 | **3** |
| длинная сторона кадра | 640 | 640 |
| пикселей на кадр | 100352 | 100352 |
| описание в промпте | 900 символов | 900 |

Товару, у которого не нашлось ни одной фотографии, подставляется белый квадрат 56×56 —
иначе промпт остаётся без места под изображение и вход меняется.

## Порядок воспроизведения

Шаги нулевого этапа видеокарты не требуют и идут параллельно обучению.

```bash
python scripts/eda_01_images.py                          # индекс изображений, ~20 мин
python scripts/eda_02_groups.py                          # группы дублей и фолды
python scripts/build_ocr_index.py -o ocr.max_images=2     # распознавание, ~4 ч
python scripts/train_linear_best.py                       # линейная ветка, минуты
```

⚠ Разбиение обязано быть **групповым**: почти-дубликаты карточек иначе попадают
и в обучение, и в проверку, и метрика завышается почти на двадцать пунктов.
Готовое разбиение лежит в `artifacts/splits/groups.parquet`; пересчёт другой
версией кода сдвинет фолды.

### Первая ступень — обе категории, три эпохи

```bash
python scripts/train_vlm_sft.py --smoke --name smoke     # проверка кода за минуту
python scripts/train_vlm_sft.py --name vlm_big_e5 \
  -o vlm.model_id=Qwen/Qwen3-VL-4B-Instruct \
  -o vlm.lora_r=32 -o vlm.lora_alpha=64 \
  -o vlm.lora_target_modules='["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"]' \
  -o vlm.use_all_data=true -o vlm.max_samples=13000 -o vlm.max_images=5 \
  -o vlm.batch_size=1 -o vlm.grad_accum=16 -o vlm.epochs=3.0
```

Признак, что всё верно: в журнале «обучающих примеров: 10376 (позитивов 4611)»,
обучаемых параметров 66 060 288, потери идут 0.20 → 0.02 монотонно.

### Вторая ступень — только редкая категория, одна эпоха

```bash
python scripts/train_vlm_sft.py --name vlm_rare2_a --resume \
  <те же ключи, что выше> \
  -o vlm.init_adapter=artifacts/models/vlm_big_e5 \
  -o vlm.only_category=Легковоспламеняющиеся \
  -o vlm.epochs=1 -o vlm.lr=2.0e-5
```

⚠ Потери здесь начинаются на уровне 1e-6 — модель уже обучена, и это норма, а не
признак того, что обучение не идёт. Признак правильного запуска: в журнале
«продолжаем адаптер», и шагов 344, а не 1947.

### Связка и рабочая точка

```bash
python scripts/eval_vlm.py --model artifacts/models/vlm_rare2_a --name vlm_rare2_a_holdout
python scripts/train_vlm_blend.py --name vlm_blend_rare2_a \
  --vlm-holdout artifacts/preds/vlm_rare2_a_holdout_holdout.parquet \
  --linear-oof artifacts/preds/svm_c4_bal_oof.parquet
python scripts/clone_blend.py --src artifacts/models/vlm_blend_rare2_a.joblib \
  --dst artifacts/models/vlm_blend_rare2_a_t24.joblib \
  --vlm-weight "БАД=0.5" --vlm-weight "Легковоспламеняющиеся=1.0"
```

⚠ Веса связки **фиксируются рецептом, а не подбираются**. Подбор идёт на
отложенной выборке, где у редкой категории 37 положительных примеров, и на них
он выбирает вес редкой 0.05 — то есть почти выключает зрительную модель там, где
она сильнее всего.

### Сборка архива

```bash
python scripts/pack_model.py --src <кэш HF>/Qwen3-VL-4B-Instruct --dst artifacts/models/qwen4b_packed
python scripts/build_submission.py --variant vlm_blend_rare2_a_t24 --docker <образ>
```

Модели Qwen3-VL-4B нет в каталоге организаторов, поэтому она едет вместе с
решением, упакованная в int8 с масштабом на строку: 8.28 ГБ становятся 4.15 при
средней относительной погрешности веса 1.09%. Корреляция оценок с исходной
моделью 0.99989, вердикты совпадают полностью.

| грабля | как проявляется |
