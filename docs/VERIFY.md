# Проверка решения

Документ для проверяющей стороны. Отвечает на три вопроса:

1. **Соответствует ли код в репозитории отправленному решению?**
2. **Что именно делает решение и как это проверить самостоятельно?**
3. **Как воспроизвести решение с нуля?**

Каждый раздел независим — можно начать с любого.

---

## 0. Что понадобится

| | |
|---|---|
| Python | 3.10 или новее |
| Место на диске | около 15 ГБ, если распаковывать архив решения |
| Видеокарта | нужна только для прогона решения и обучения; проверки из разделов 1–2 идут на процессоре |
| Архив отправки | `.zip` из системы отправок, ~4.3 ГБ |

Проверки в разделах 1 и 2 **не требуют ни видеокарты, ни весов** и занимают секунды.

```bash
git clone <репозиторий>
cd ozon-tech-ecup-2026
python -m venv .venv && . .venv/bin/activate      # на Windows: .venv\Scripts\activate
pip install -r requirements-inference.txt
```

## 1. Соответствует ли код отправленному архиву

Это основной вопрос, и на него отвечает `tools/audit.py`. Он сверяет **собранный zip**, а
не дерево сборки: значение имеет то, что уехало, а не то, что собирались положить.

```bash
python tools/audit.py --zip путь/к/отправке.zip --no-weights
```

Ключ `--no-weights` означает проверку внутренней связности: образ, точка входа, состав
файлов, настройки обеих категорий, отсутствие выброшенных зависимостей. Побайтовая
сверка весов требует исходных архивов и включается отдельно (см. ниже).

### Что именно проверяется

**Общее**

| проверка | ожидание |
|---|---|
| образ решения | `odsai/ecup26-quality-baseline:1.0` — базовый, от организаторов |
| точка входа | `python -u run.py` |
| наличие обязательных файлов | `run.py`, `metadata.json`, конфиг отправки, оба адаптера, база |

**Категория «Легковоспламеняющиеся»**

| проверка | ожидание | почему важно |
|---|---|---|
| адаптер | `artifacts/sft_vlm/vlm_rare2_a` | |
| веса адаптера, sha256 | совпадают с архивом-источником | подтверждает, что модель не пересобиралась |
| способ отбора | `calibrated` | порог по эталону, а не доля |
| порог | `0.9699` | |
| длина эталона калибровки | 1101 значение | ровно отложенный фолд редкой категории |
| шаблон промпта | `rare2` | |
| обрезка описания | 900 символов | |
| кадров, пикселей на кадр | 5, 100352 | |
| написания «да» и «нет» | по 5 вариантов | от них зависит логит-разность, а порог — срез абсолютный |

**Категория «БАД»**

| проверка | ожидание | почему важно |
|---|---|---|
| адаптер | `artifacts/sft_vlm/vl4_plain_bf16` | |
| веса адаптера, sha256 | совпадают с архивом-источником | |
| способ отбора | `rate`, доля `0.5733` | |
| шаблон промпта | `qc` | |
| обрезка описания | **ключа нет** → прогон режет по 800 | это не упущение, см. README раздел 5 |

**Объяснения**

| проверка | ожидание |
|---|---|
| источник | `vlm` — пишет та же модель, что вынесла вердикт |
| потолок новых токенов | 60 |
| кадров в промпте объяснения | 1 |
| обрезка описания в промпте | 300 |

**Отсутствие выброшенного**

| проверка | ожидание | зачем |
|---|---|---|
| `import peft` в решении | **нет** | подтверждает, что подходит базовый образ |
| `easyocr`, `cv2`, `bitsandbytes` | нет | их нет в базовом образе |

### Полная сверка, с весами

Если у вас есть архивы-источники, из которых собрано решение, побайтовое сравнение
весов включается так:

```bash
python tools/audit.py \
  --zip путь/к/отправке.zip \
  --record путь/к/vlm_blend_rare2_a_t24.zip \
  --mate   путь/к/vl4_plain.zip
```

Отчёт заканчивается строкой `ИТОГ: сошлось N, расхождений M`. При любом расхождении
код возврата ненулевой, и видно **какая именно** строка не сошлась — а не «архивы
разные».

⚠ Если архивов-источников нет, скрипт скажет об этом вслух и продолжит без сверки
весов. Урезанный отчёт не выдаётся за полный.

## 2. Проверить сам код, не запуская модель

### Ручная вживка LoRA эквивалентна `peft`

Ключевое утверждение решения: `peft` не нужен, потому что LoRA складывается в веса
вручную. Проверяется без загрузки модели:

```bash
python - <<'EOF'
import sys, json, tempfile, pathlib, torch
sys.path.insert(0, "src")
from safetensors.torch import save_file
from qc26.inference.vlm import apply_lora

class Tiny(torch.nn.Module):
    def __init__(s):
        super().__init__()
        s.language_model = torch.nn.Module()
        s.language_model.q_proj = torch.nn.Linear(8, 6, bias=False)

torch.manual_seed(0)
m = Tiny(); w0 = m.language_model.q_proj.weight.detach().clone()
A, B, r, alpha = torch.randn(4, 8), torch.randn(6, 4), 4, 8
with tempfile.TemporaryDirectory() as d:
    p = pathlib.Path(d)
    save_file({"base_model.model.language_model.q_proj.lora_A.weight": A,
               "base_model.model.language_model.q_proj.lora_B.weight": B},
              str(p / "adapter_model.safetensors"))
    (p / "adapter_config.json").write_text(json.dumps(
        {"r": r, "lora_alpha": alpha, "target_modules": ["q_proj"]}), encoding="utf-8")
    n = apply_lora(m, p)

want = w0 + (B @ A) * (alpha / r)
got = m.language_model.q_proj.weight.detach()
print("слоёв изменено:", n)
print("наибольшее отличие от формулы W + (B@A)*(alpha/r):",
      float((got - want).abs().max()))
EOF
```

Ожидается `слоёв изменено: 1` и отличие `0.0`.

На настоящем адаптере сверка с `peft` даёт **0.000e+00 на 713 параметрах** — формула
`peft.tuners.lora.layer.Linear.get_delta_weight` тождественна нашей при
`fan_in_fan_out: false`, что и записано в конфигурации адаптеров.

### Упаковка базы в int8 обратима

```bash
python - <<'EOF'
import sys, torch; sys.path.insert(0, "src")
from qc26.models.packing import _pack_tensor, _unpack_tensor
torch.manual_seed(0)
w = torch.randn(512, 512) * 0.02
q, scale = _pack_tensor(w)
back = _unpack_tensor(q, scale, torch.float32)
err = (w - back).abs().mean() / w.abs().mean()
print(f"средняя относительная погрешность: {float(err):.4f}")
print("размер до:", w.numel() * 4, "после:", q.numel() + scale.numel() * 4)
EOF
```

Ожидается погрешность **около 0.008** и сжатие вчетверо (1 048 576 байт → 264 192).

⚠ На синтетическом нормальном тензоре погрешность выходит ниже, чем на настоящей
модели: в README указано **0.011** — это среднее по всем 358 тензорам базы, где
распределения весов разные и хвосты тяжелее. Сжатие в обоих случаях вчетверо.

### Настройки входа читаются из журнала обучения, а не из констант

```bash
python - <<'EOF'
import json, pathlib
for a in ("vlm_rare2_a", "vl4_plain_bf16"):
    p = pathlib.Path("artifacts/sft_vlm") / a / "train_log.json"
    d = json.loads(p.read_text(encoding="utf-8"))
    print(a, "->", {k: d.get(k) for k in
          ("prompt", "desc_max", "n_images", "max_pixels", "image_max_side")})
EOF
```

Видно, что у двух адаптеров **разные** шаблон промпта и обрезка описания. Если бы код
использовал одну константу на оба, вход одной из моделей оказался бы из другого
распределения — без ошибки, только с тихо съехавшим вердиктом.

## 3. Запустить решение

### На готовом архиве

```bash
unzip отправка.zip -d solution && cd solution
docker run --rm --gpus all \
  -v "$PWD":/w -v /путь/к/данным:/data:ro -w /w \
  odsai/ecup26-quality-baseline:1.0 \
  python -u run.py --test_data_path /data/test.csv --output_path /w/out.csv
```

Образ — базовый, от организаторов; своего образа решение не собирает.

### Что должно быть в выводе

| строка | значение |
|---|---|
| `веса упакованы в int8 — разворачиваю` | база распаковывается на лету |
| `LoRA вживлена в 252 слоёв (без peft)` | адаптер применён; 252 = 36 слоёв × 7 проекций |
| `батч прогона: N (свободно X ГБ ...)` | батч посчитан по фактической памяти карты |
| `источник вердикта: модель + VLM` | зрительная модель задействована |
| `объяснения ... моделью N, шаблон 0` | **шаблон 0** означает, что все объяснения порождены моделью |

⚠ Если в последней строке шаблон **не ноль** — часть объяснений подменена заготовками
из правил. Формат при этом валиден и балл не падает, поэтому заметить это можно только
по этой строке.

⚠ Если зрительная модель недоступна, решение **завершается с ошибкой**, а не выдаёт
вердикт текстовой модели. Это сделано намеренно: тихое вырождение однажды дало три
отправки с одинаковым до десятого знака баллом, и распознать его по результату было
нельзя.

### Время прогона

Замерено на проверяющей конфигурации:

| стадия | товаров | лимит | фактически |
|---|---|---|---|
| отладочная | 10 | 3 мин | секунды |
| публичная | 1600 | 20 мин | около 12 мин |
| приватная | 3789 | 40 мин | около 28 мин |

## 4. Проверить перенос калибровки

Отдельная проверка того, что порог `0.9699` переносится на новые данные. Она отвечает
на вопрос «не подогнан ли порог под публичную выборку».

```bash
python tools/check_calib.py           # готовит выборку отложенного фолда
python tools/check_calib.py --score   # считает оценки и сверяет с эталоном
```

На отложенном фолде (1101 товар, 37 положительных):

```
распределения совпали на квантилях 0.50 / 0.90 / 0.95 / 0.99
порог отбирает 3.72% выборки        (на публичной выборке было 3.11%)
качество:  порог     отобрано 41, верных 24 из 37, F1 0.6154
           доля 3.11% отобрано 34, верных 21 из 37, F1 0.5915
```

⚠ F1 0.6154 на отложенном фолде против 0.9130 на публичной выборке — разрыв большой и
объясним размером выборки: в редкой категории публичной выборки **24 положительных
товара**, и один товар стоит 4.3 пункта F1 категории. Оба числа — броски из одного
распределения, просто публичный оказался удачным.

## 5. Воспроизвести обучение с нуля

Полный порядок с командами — в README, раздел 6. Здесь только время и контрольные точки.

| шаг | время | признак, что всё верно |
|---|---|---|
| индекс изображений | ~20 мин | без видеокарты |
| группы и фолды | ~10 мин | без видеокарты |
| распознавание текста | ~4 ч | без видеокарты, нужно только линейной ветке |
| первая ступень | 20.5 ч на RTX 3060 Ti | «обучающих примеров: 10376 (позитивов 4611)», потери 0.20 → 0.02 |
| вторая ступень | 7.6 ч | «продолжаем адаптер», 344 шага |
| связка и рабочая точка | 3 мин | веса ровно `{БАД: 0.5, Легковоспламеняющиеся: 1.0}` |
| упаковка базы | ~20 мин | 8.28 ГБ → 4.15 ГБ |

⚠ Разбиение обязано быть групповым: при случайном метрика завышается почти на двадцать
пунктов из-за почти-дубликатов карточек. Готовое разбиение —
`artifacts/splits/groups.parquet`; пересчёт другой версией кода сдвинет фолды, и модель
обучится на строках, на которых её потом меряют.

## 6. Известные грабли

Все перечисленные — **молчаливые**: решение отрабатывало, писало «готово» и выдавало
файл верного формата.

| грабля | как проявлялась | как закрыта |
|---|---|---|
| случайное разбиение вместо группового | метрика завышена на ~20 пунктов | групповое разбиение зафиксировано в `groups.parquet` |
| подбор весов связки по отложенной выборке | вес редкой 0.05 вместо 1.0, минус 3.6 пункта | веса фиксируются рецептом |
| продолжение адаптера без `is_trainable` | обучение шло вхолостую, без единой ошибки | проверяется строкой «продолжаем адаптер» и падением потерь |
| крошечные потери на второй ступени | принимались за «не учится», прогон убивали | 1e-6 — норма для продолжения |
| порог вместо доли в БАД | шкала не переносится на закрытые данные | в БАД доля, в редкой порог по эталону |
| одна константа длины описания на два адаптера | вход одной модели из другого распределения | длина читается из журнала адаптера |
| разные написания «да» и «нет» | другая логит-разность при том же пороге | написания читаются из журнала адаптера |
| тихий откат при сбое зрительной модели | решение вырождалось в текстовое и возвращало валидный балл | решение падает |
| батч под свою карту | проверяющая карта простаивает | батч по фактической свободной памяти |
| нехватка памяти на отдельном батче | товары молча получали нейтральную оценку | батч дробится пополам и досчитывается |

## 7. Если что-то не сошлось

`tools/audit.py` печатает по строке на каждую проверку и в конце `ИТОГ: сошлось N,
расхождений M`. При расхождении видно ожидаемое и полученное значение — этого
достаточно, чтобы понять, в чём разница, без чтения кода.

Наиболее вероятные причины расхождений:

- **разные веса адаптера** — архив собран из другого прогона обучения;
- **другой порог или длина эталона** — использован иной шаг рабочей точки;
- **есть `import peft`** — собрана версия под свой образ, а не под базовый;
- **шаблон промпта не тот** — журнал обучения не доехал вместе с адаптером.
