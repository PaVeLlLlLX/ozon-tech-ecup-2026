---

Решение задачи «Контроль качества»: по карточке товара (название, описание, фотографии)
определить, действительно ли товар относится к заявленной продавцом категории, и
объяснить решение словами. Оценка — среднее двоичных F1 по классу «не бан», посчитанных
внутри каждой из двух категорий.

## Главная идея

Метрика усредняет категории **независимо**, поэтому в каждой работает то дообучение,
которое её выигрывает, и по тому правилу отбора, по которому оно её выиграло.

| категория | адаптер | отбор | измеренный F1 |
|---|---|---|---|
| Легковоспламеняющиеся | `vlm_rare2_a` | порог 0.9699 по калиброванной шкале | 0.9130 |
| БАД | `vl4_plain_bf16` | доля 0.5733 | 0.9280 |

Числа получены разложением публичных баллов по известному составу выборки: в категории
«БАД» 921 товар и 528 подходящих, в «Легковоспламеняющихся» — 707 и 24. При таком составе
публичный балл раскладывается на две категории однозначно.

## Как устроен прогон

Основа обеих половин — **Qwen3-VL-4B-Instruct**, дообученная методом LoRA. Модель
получает карточку и до пяти фотографий и отвечает одним словом «Да» или «Нет» на вопрос,
относится ли товар к заявленной категории.

Оценка берётся из логитов первого токена ответа как **разность**
`logsumexp(«да») − logsumexp(«нет»)`, а не из сгенерированного текста.

### Отбор

⚠⚠ **Порог привязан к конкретному сжатию базовой модели.** Эталон снят на той стопке
весов, где тензор `model.visual.pos_embed.weight` зрительной части хранится СЖАТЫМ в
int8. Обычная упаковка базы оставляет его несжатым, и тогда оценки смещаются: замерено
на лидерборде, что при несжатом варианте один подходящий товар из двадцати четырёх
уходит ниже отбора, а это около трёх пунктов общей метрики. Поэтому после упаковки базы
её нужно привести к тому же виду:

```bash
python scripts/align_base.py --check    # показать расхождение
python scripts/align_base.py --apply    # привести
```

Скрипт повторяет сжатие редкой половины дословно — масштаб на строку, `max|w| / 127` — и кладёт
развёрнутый результат обратно. Это не «улучшение» весов, а условие применимости порога:
несжатый тензор точнее, но порог калиброван не на нём.


**«Легковоспламеняющиеся» — абсолютный порог.** Оценка переводится в квантиль
относительно эталонного распределения из 1101 значения, снятого на отложенной выборке
(`artifacts/models/rare2_calibration.json`), и сравнивается с порогом 0.9699. Критерий
абсолютный: «оценка выше 96.99% эталона».

**«БАД» — доля.** Называются верхние 57.33% проверяемой выборки.

⚠ Правила разные не по недосмотру. В редкой категории порог замерен против доли на
отложенной выборке из 1101 товара с 37 подходящими: **F1 0.6154 против 0.5915**. В «БАД»
доля — то правило, на котором получен её результат, и менять его не на чем.

### Объяснение вердикта

Комментарий пишет **та же модель, которая вынесла вердикт в этой категории**: она
описывает, что находится внутри товара и от чего он работает.

⚠⚠ Подсказка в промпте **не знает вердикта**: подсказки для «бан» и «не бан» выровнены
посимвольно. Иначе модель перестаёт описывать товар и начинает подыскивать оправдание уже
принятому решению. Побочный итог: получившийся текст сам по себе предсказывает разметку в
редкой категории с AUC 0.93 — модель проговаривает различие «внутри собственное топливо»
против «работает от внешнего источника», которое ключевыми словами не выражается.

Длина комментария приводится к 50–300 символам, вердикт — строго «бан» или «не бан».
Формат проверяется валидатором перед записью файла.

## Настройки — свойство адаптера, а не константа кода

Две модели обучались по-разному, и водить их одинаково нельзя. Всё, что влияет на вход и
на шкалу оценки, читается из `train_log.json` рядом с адаптером:

| ключ | `vlm_rare2_a` | `vl4_plain_bf16` |
|---|---|---|
| шаблон промпта | `rare2` | `qc` |
| обрезка описания | 900 символов | 800 |
| кадров | 5 | 5 |
| пикселей на кадр | 100352 | 100352 |
| написаний ответа | по 5 на класс | по умолчанию |

⚠ Расхождение хотя бы в одном из этих пунктов не вызывает ошибки — оно молча меняет
вердикт. Шаблон `rare2` отличается от соседнего одним переносом строки, и этого
достаточно, чтобы вход стал другим.

## Ресурсы контейнера

Решение едет на **базовом образе организаторов** и ничего в него не доставляет.

- **peft не нужен**: LoRA вживляется в веса вручную (`src/qc26/inference/vlm.py`,
  `apply_lora`) — результат сверен с `peft` побитово;
- **распознавание текста на фотографиях убрано**: в конфиге обучения адаптера редкой
  категории стоит `use_ocr: false`, то есть распознанный текст в её промпт не подавался
  никогда;
- база везётся в архиве упакованной в int8 с масштабом на строку.

В контейнере файловая система только для чтения и нет сети: решение ничего не скачивает и
не пишет никуда, кроме `--output_path`.

## Запуск

```bash
python -u run.py --test_data_path <входной csv> --output_path <выходной csv>
```

Ровно этот вызов делает проверяющая система, своих аргументов она не передаёт.

## Что где лежит

```
run.py                     точка входа: --test_data_path / --output_path
src/qc26/
  inference/vlm.py         ручная вживка LoRA, оценка, чтение настроек адаптера
  inference/exotic.py      загрузка модели для прохода генерации
  inference/format.py      сборка строки ответа и валидатор формата
  explain/vlm_explain.py   генерация объяснений
  explain/templates.py     шаблонное объяснение — опора и запасной путь
  models/packing.py        распаковка весов из int8
  models/text_baseline.py  линейная модель на частотах слов
  rules.py                 правила категорий: признаки и каркас объяснений
configs/
  submission.yaml          что отправляем: адаптеры, правила отбора, объяснения
  data.yaml, baseline.yaml раскладка данных и текстовая ветка
  prompts/                 вопрос модели и правила категорий
artifacts/
  models/rare2_calibration.json   эталон и порог редкой категории
  sft_vlm/*/train_log.json        как водить каждый адаптер
scripts/pack_submission.py сборка архива решения с проверкой собранного
scripts/align_base.py      приведение базы к сжатию, на котором калиброван порог
training/rare/               обучение адаптера редкой категории (свой пакет)
training/supplement/         обучение адаптера БАД (против пакета решения)
docker/metadata.json       образ и точка входа
tools/
  audit.py                 сверка собранного архива с источниками
  check_calib.py           состоятельность переноса порога на новые данные
docs/VERIFY.md             инструкция для проверяющей стороны
```

⚠ Обучающие конфигурации лежат **рядом со своей половиной** — в `training/rare/configs/`
и `training/supplement/`, а не в общем каталоге. Половины обучались по-разному, и общий
общий конфиг обучения создавал бы впечатление, что настройка одна на обе. В `configs/`
остаётся только то, что читает прогон.

⚠ Модули `inference/embed.py` и `models/emb_head.py` решением не используются: ветка с
головой над векторами фотографий закрыта, и ключа `emb_head` в конфиге нет. Они остаются
потому, что на них ссылается `run.py`, а он обязан совпадать с уехавшим архивом побайтово.

⚠ Веса моделей в репозиторий не входят: они превышают его разумный размер и едут в архиве
решения. В `artifacts/` лежат только описания — эталон калибровки и журналы обучения,
без которых адаптеры нельзя завести правильно.


## Проверка решения

Подробная инструкция для проверяющей стороны — **[docs/VERIFY.md](docs/VERIFY.md)**.
Там же три проверки кода, которым не нужны ни видеокарта, ни веса: эквивалентность
ручной вживки LoRA формуле `peft`, обратимость упаковки в int8 и чтение настроек входа
из журналов обучения.

```bash
python tools/audit.py --zip <проверяемый архив> --no-weights
```

Сверяются образ и точка входа, состав файлов, настройки обеих категорий, порог и длина
эталона калибровки, настройки объяснений и отсутствие выброшенных зависимостей. Ключи
`--record` и `--mate` добавляют побайтовую сверку весов адаптеров с архивами-источниками.

⚠ Отдельно проверяется состоятельность переноса порога на данные, которых модель не
видела: `python tools/check_calib.py --score`. Это ответ на вопрос, не подогнан ли порог
0.9699 под публичную выборку.

## Воспроизведение

Половины обучались разным кодом на разных машинах, поэтому обучающие ветви разведены и
не пересекаются. Пакет решения `src/qc26` при этом общий: ветвь «БАД» работает прямо
против него, ветви редкой категории нужен свой — её модули разошлись с ним по сути.

### Адаптер редкой категории `vlm_rare2_a`

```bash
python training/rare/train_vlm_sft.py --config training/rare/configs/vlm_sft_rented.yaml
```

LoRA ранга 32 при alpha 64 на семи проекциях, три прохода по данным, 5 кадров,
100352 пикселя, описание 900 символов, `use_ocr: false`. Собственный пакет ветви —
`training/rare/qc26/`.

Эталон калибровки строится там же: распределение оценок обученной модели на 1101 товаре
редкой категории отложенного фолда. Порог берётся по нему и лежит в
`artifacts/models/rare2_calibration.json`.

### Адаптер категории «БАД» `vl4_plain_bf16`

```bash
PYTHONPATH=src python training/supplement/sft_vlm_lora.py --stage train     --split fold_seed42 --fold 0 --use-all-folds --inner-fold 4     --n-images 5 --prompt qc --lora-rank 32 --lora-alpha 64     --max-steps 1946 --batch 1 --accum 16 --lr 1e-4 --select-by recall
```

Точные значения всех аргументов того прогона, который дал результат, записаны в
`artifacts/sft_vlm/vl4_plain_bf16/train_log.json` — там же лежат и те, что не вынесены
в команду выше.

⚠ Разброс между прогонами одного и того же рецепта в редкой категории велик: обучение по
тем же настройкам дало 18 верных вместо 21, то есть 6.8 пункта общей метрики. При двух
десятках подходящих товаров на категорию один товар стоит больше двух пунктов, и такой
разброс здесь норма, а не признак поломки.

## Сборка архива

```bash
python scripts/pack_submission.py
```

Собранный zip проверяется изнутри: конфиг, наличие обоих адаптеров, базовый образ,
целостность. Веса при этом должны лежать в `artifacts/` — в репозиторий они не входят.

## Разбиение данных

Замеры считаются только на **групповых** разбиениях: почти-дубликаты карточек собраны в
группы по тексту и хэшам фотографий и не расходятся между обучением и проверкой. На
случайном разбиении метрика завышается на 19.5 пункта.
